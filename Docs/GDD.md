# MERRY MEMORY — Game Design Document

**A Christmas Story for You**
Unity 6 기반 2D 픽셀 퍼즐 어드벤처 · 크리스마스 이벤트 게임

> 이 문서는 게임의 방향과 요구사항을 정리한 기준 문서다. 기획·설계·개발은 이 문서를 기준으로 진행하며, 아직 정하지 않은 항목은 [14. 미정 사항](#14-미정-사항)에 모아 둔다.

### 1.1 한 줄 소개
크리스마스이브, 작은 눈 마을의 임시 집배원이 흩어진 크리스마스카드 조각을 모아 마지막 배달을 떠난다.
받는 사람은 바로 **화면 너머에서 플레이하고 있는 당신**이다.

## 2. 핵심 메시지

> **화면 밖에서 플레이하고 있는 플레이어에게 "MERRY CHRISTMAS!!"라는 인사를 건넨다.**

이 게임에서 절대 바뀌지 않아야 하는 유일한 요소다. 스토리, 퍼즐, 연출은 모두 이 인사가 자연스럽고 따뜻하게 전달되도록 돕는 장치다.

- 엔딩에서 게임 속 인물들이 **화면 정면의 플레이어**에게 직접 인사한다.
- 공포·충격 반전이 아니라 **선물을 받는 기분**으로 끝나야 한다.
- 플레이어가 엔딩 전에 받는 사람을 눈치채도 괜찮다. 이 게임의 목적은 놀라게 하는 것이 아니라 인사하는 것이다.

## 3. 스토리

### 3.1 시놉시스
12월 24일 저녁, 작은 눈 마을의 우체국.
크리스마스 대목을 맞아 일하게 된 임시 집배원(주인공)이 오늘의 배달을 거의 끝냈을 때, **딱 한 장의 카드**가 남아 있다. 마을 사람 모두가 함께 만든 커다란 팝업 크리스마스카드다.

그런데 창문으로 들이친 눈바람에 카드가 **다섯 조각으로 흩어져** 마을 곳곳으로 날아가 버렸다. 게다가 봉투의 주소는 젖어서 알아볼 수 없다.

자정 전에 배달해야 하는 카드. 주인공은 조각을 찾아 마을을 돌아다니고, 조각을 만든 사람들에게 **받는 사람이 누구인지** 묻는다.
모두가 알쏭달쏭한 단서만 남긴다. "아주 먼 곳에 사는 사람", "우리를 계속 지켜봐 주던 사람", "너를 여기까지 걸어오게 한 사람"…

다섯 조각을 모두 모아 카드를 완성한 순간 주소가 드러난다.

> **To. 화면 너머의 너에게**

### 3.2 프롤로그
1. **명찰 작성** (캐릭터 설정, [6장](#6-캐릭터-설정-명찰-작성) 참고). 우체국장이 도장을 찍어 주면 게임이 시작된다.
2. 우체국. 우체국장이 마지막 카드를 보여 주려는 순간 눈바람이 들이치고, 카드 조각이 흩어진다.
3. 목표 제시
   > 우체국장: "자정 전에 배달해야 하는 카드인데…!"
   > {이름}: "제가 찾아올게요. 근데 이거, 누구한테 가는 카드예요?"
   > 우체국장: "그게… 봉투 주소가 젖어서 번져 버렸지 뭐야."

### 3.3 진행
- **목표 1:** 카드 조각 5개 모으기
- **목표 2:** 받는 사람 알아내기

조각마다 그 조각을 만든 마을 사람이 있다. 퍼즐로 그 사람을 도와 조각을 받으면:
1. 그 사람이 **카드에 받는 사람에게 보내는 한마디**를 적어 준다. 이 한마디들이 엔딩에서 카드가 펼쳐질 때 하나씩 떠오른다.
2. **받는 사람에 대한 단서**를 하나 알려 준다. 단서는 가볍고 장난스럽게 쓰며, 주인공이 매번 엉뚱하게 해석하는 것이 웃음 포인트다.
   > {이름}: "날 여기까지 걸어오게 한 건… 내 다리인데?"

### 3.4 엔딩
1. 자정 직전, 광장의 크리스마스트리 앞에 마을 사람들이 모두 모인다.
2. 조각 다섯 개를 맞춰 카드를 완성한다. 쉬운 마무리 퍼즐로, 의식에 가깝다.
3. 봉투의 주소가 보인다: **"To. 화면 너머의 너에게"**
4. 주인공이 잠시 멈췄다가, 천천히 **화면 정면**을 본다.
   > {이름}: "…아. 그래서 다들 그렇게 말한 거구나."
   > {이름}: "날 여기까지 데려와 준 거, 너였구나."
5. 자정 종이 울리고, 카드가 펼쳐지며 캐럴(3번 조각의 멜로디)이 흘러나온다. 마을 사람들의 한마디가 하나씩 떠오른다.
6. 주인공이 카드를 화면 쪽으로 내민다.
   > {이름}: "배달 왔습니다! 우리 마을 모두가 너한테 보내는 카드야."
   > {이름}: "같이 와 줘서 고마워. 그럼, 다 같이—"
   > 모두: **"MERRY CHRISTMAS!!"**

### 3.5 엔딩 이후
- **크레딧:** 카드의 보내는 사람 칸 형식으로 연출한다. 마을 사람들, 주인공 {이름}, 그리고 **이 게임의 제작자** 이름이 함께 적힌다. 실제 제작자가 플레이어에게 보내는 인사가 된다.
- **타이틀 화면 변화:** 엔딩을 본 뒤에는 타이틀 화면의 우체통에 **"배달 완료"** 도장이 찍혀 있다. 이를 위해 엔딩 클리어 여부를 영구 저장해야 한다.

## 4. 등장인물

### 4.1 주인공
- 제작자가 직접 만든 캐릭터(자캐)를 바탕으로 한다. 헤드폰, 짙은 색 후드, 목걸이 명찰이 특징이다.
- 크리스마스 대목에 마을 우체국에서 일하게 된 **임시 집배원**이다. 스프라이트의 목걸이 명찰을 집배원 명찰로 쓴다.
- **적당히 말을 하는 주인공.** 혼잣말과 짧은 대답 위주로 쓴다.
- 이름과 성별은 플레이어가 정한다([6장](#6-캐릭터-설정-명찰-작성)).

### 4.2 마을 사람들
각 조각을 만든 사람이자 받는 사람에게 한마디를 남기는 사람들이다. 이름과 세부 성격은 미정이다.

| 인물 | 장소 | 역할 |
|---|---|---|
| 우체국장 | 우체국 | 의뢰인. 튜토리얼 안내 |
| 장난감 공방 주인 | 장난감 공방 | 팝업 트리 조각 제작자 |
| 종지기 | 시계탑 | 멜로디 칩 조각 제작자 |
| 눈 언덕의 아이들 | 눈 언덕 | 리본 조각 제작자 |
| 빵집 사장 | 빵집 | 봉투 조각 제작자 |

## 5. 게임 구조

### 5.1 카드 조각
| # | 장소 | 조각 | 퍼즐 (안) | 받는 사람 단서 (안) |
|---|---|---|---|---|
| 1 | 우체국 *(튜토리얼)* | 📮 우표 | 뒤섞인 우편물을 주소대로 분류 | "아주 먼 곳에 사는 사람이래." |
| 2 | 장난감 공방 | 🎄 팝업 트리 | 망가진 팝업 장치 재조립 | "오늘 우리 마을에 처음 와 준 사람이야." |
| 3 | 시계탑 | 🎵 멜로디 칩 | 종을 올바른 순서로 쳐서 캐럴 완성 | "우리를 계속 지켜봐 주던 사람이지." |
| 4 | 눈 언덕 | 🎀 리본 | 얼음 미끄럼 퍼즐로 나무에 걸린 리본 회수 | "그 사람은 늘 네 곁에 있었어." |
| 5 | 빵집 | ✉️ 봉투 | 번진 주소의 글자를 단서로 복원 | "너를 여기까지 걸어오게 한 사람이잖아?" |

- 1번은 튜토리얼로 고정한다. 2~5번은 **순서 없이 자유롭게** 진행한다.
- 5번(봉투)은 받는 사람과 직접 이어지는 조각이다. 자유 진행이므로 어떤 순서로 모아도 단서가 자연스럽게 읽히도록 대사를 쓴다.
- 퍼즐 세부 기믹은 개발하면서 바뀔 수 있다. 다만 **조각 = 마을 사람의 한마디 + 받는 사람 단서** 구조는 유지한다.

### 5.2 조각 획득 연출
1. 짧은 효과음과 함께 조각 획득 UI가 표시된다.
2. 마을 사람이 카드에 한마디를 적는 짧은 장면이 나온다(내용은 엔딩까지 가려 둘 수 있음).
3. 받는 사람 단서 대사가 나온다.
4. 카드 진행 현황 UI에 조각이 채워진다.

### 5.3 플레이 흐름
```
명찰 작성 → 프롤로그(우체국) → 조각 1(튜토리얼)
  → 조각 2~5 (자유 순서)
  → 광장 트리: 카드 완성 → 엔딩 → 크레딧 → 타이틀("배달 완료")
```

## 6. 캐릭터 설정 (명찰 작성)
이름·성별 입력을 메뉴 대신 **"임시 집배원 명찰 작성"** 화면으로 연출한다.

- **사진 칸:** 성별에 따라 스프라이트 두 가지 중 하나를 고른다. 고른 캐릭터가 손 흔드는 동작을 보여 준다.
- **이름 칸:** 이름을 입력한다. 한글 기준 최대 6자 정도로 제한한다(대화창 줄 넘침 방지).
- **확인:** "○○(으)로 할까요?" → 우체국장이 도장을 찍어 주면 시작한다.

### 6.1 규칙
- **성별은 스프라이트만 바꾼다.** 대사는 하나로 쓰고 성별에 따라 나누지 않는다.
- **이름 뒤 조사는 자동으로 처리한다.** 이름의 받침 유무에 따라 조사가 바뀐다.
  - 대사 표기 예: `{이름}{이/가}`, `{이름}{은/는}`, `{이름}{을/를}`, `{이름}{아/야}`, `{이름}{과/와}`, `{이름}{으로/로}`
  - "지민**이** 왔구나" / "하나**가** 왔구나", "지민**아**!" / "하나**야**!"
  - 한글이 아닌 이름(영문 등)은 받침이 없는 것으로 처리한다.

## 7. 퍼즐 및 상호작용

### 7.1 기본 상호작용
오브젝트 조사, 마을 사람과 대화, 아이템 획득·사용, 장치 조작, 조건부 이벤트.

### 7.2 퍼즐 원칙
- 이벤트 게임이므로 **전체적으로 쉽게** 만든다. 막혀서 그만두는 일이 없어야 한다.
- 같은 유형을 반복하지 않는다(분류, 조립, 소리 순서, 미끄럼, 글자 복원).
- **힌트:** 같은 곳에서 오래 머물거나 퍼즐을 여러 번 틀리면, 주인공의 혼잣말이나 근처 마을 사람이 힌트를 준다.

## 8. 아트 및 사운드

### 8.1 그래픽
- 2D 픽셀 아트, 탑다운 시점, 타일맵 기반 마을
- 눈 내리는 밤의 작은 마을. 차가운 밤하늘과 창문의 따뜻한 불빛이 대비를 이룬다.
- 주인공 스프라이트는 제작자가 직접 제공한다(성별 2종, 4방향 걷기 + 감정 표현 프레임).
- 엔딩의 "화면 정면 보기"는 탑다운 스프라이트만으로는 구분이 약하므로, **정면 클로즈업 일러스트**나 카메라 줌인으로 강조한다.
- UI도 픽셀 아트 스타일로 맞춘다. 카드·우표·도장 모티프를 활용한다.

### 8.2 사운드
- 잔잔한 크리스마스 캐럴(저작권이 만료된 곡 활용, 예: 「징글벨」)
- 눈 밟는 발소리, 바람 소리, 우체국 도장 소리, 종소리, 장난감 태엽 소리, 오븐 소리
- 조각 획득 효과음
- 엔딩: 3번 조각에서 완성한 캐럴 멜로디를 카드가 펼쳐질 때 다시 들려준다.

## 9. 기술 방향

### 9.1 기술 스택
| 항목 | 선택 |
|---|---|
| 엔진 | Unity 6 (6000.3.x) |
| 렌더링 | Universal Render Pipeline 2D (URP 2D) |
| 맵 | Unity 2D Tilemap |
| 입력 | Unity Input System |
| 텍스트 | TextMeshPro + 한글 지원 폰트(픽셀 한글 폰트 검토, 예: Galmuri·OFL) |
| 데이터 | ScriptableObject (대사, 아이템, 조각 정보) |

### 9.2 주요 시스템
- **PlayerController:** 탑다운 이동, 4방향 애니메이션, 이동 잠금
- **InteractionSystem:** 상호작용 대상 탐지, 조사·대화 실행, 안내 UI
- **DialogueSystem:** 대사 출력, 이름·조사 치환(`{이름}{이/가}`), 선택지
- **PlayerProfile:** 이름·성별 저장, 성별에 따른 스프라이트 적용
- **CardPieceSystem:** 조각 획득 상태, 진행 UI, 카드 완성 조건 확인
- **PuzzleSystem:** 퍼즐별 진행·해결 처리와 환경 변화
- **SaveSystem:** 진행 저장(이름·성별·조각·퍼즐), 엔딩 클리어 플래그(타이틀 변화용)

### 9.3 프로젝트 구조 (안)
```
Assets/
├── Art/          (Characters, Tilesets, Objects, UI, Effects)
├── Audio/        (BGM, SFX, Ambience)
├── Animations/
├── Prefabs/      (Characters, Interactables, UI)
├── Scenes/       (Title, NameBadge, Village, Ending)
├── Scripts/      (Core, Player, Interaction, Dialogue, Puzzle, Card, UI, Audio, Save)
├── ScriptableObjects/ (Dialogues, Items, CardPieces)
└── Settings/
```

## 10. 조작 및 UI
- WASD / 방향키: 이동 · E / Space: 상호작용, 대사 넘기기 · ESC: 메뉴
- 주요 UI: 타이틀, 명찰 작성, 대화창, 상호작용 안내, 카드 조각 현황, 퍼즐 UI, 일시정지 메뉴

## 11. 개발 우선순위
핵심 메시지(엔딩)를 일찍 검증하기 위해 **처음부터 끝까지 이어지는 최소 버전**을 먼저 만든다.

1. **기본 플레이:** 프로젝트 생성, 플레이어 이동, 카메라, 타일맵, 상호작용, 대화
2. **최소 흐름(버티컬 슬라이스):** 명찰 작성 → 프롤로그 → 조각 1개 → 엔딩. 이 단계에서 엔딩 인사가 잘 전달되는지 확인한다.
3. **핵심 시스템:** 조각 시스템, 퍼즐 틀, 세이브
4. **구역 제작:** 조각 2~5와 각 퍼즐
5. **연출·콘텐츠:** 대사, 단서, 카드 메시지, 사운드, 눈 효과, 크레딧, 타이틀 변화
6. **마무리:** 전체 흐름 점검, 난이도 조정, 버그 수정, 플레이 타임 확인

## 12. 개발 지침
1. 게임의 목적은 **플레이어에게 "MERRY CHRISTMAS!!"를 전하는 것**이다. 이와 어긋나는 변경은 하지 않는다.
2. 분위기는 가볍고 따뜻하게 유지한다. 공포·충격 요소는 넣지 않는다.
3. 카드 조각 5개를 중심으로 한 진행 구조를 유지한다. 퍼즐 세부는 바뀌어도 된다.
4. 시스템 간 결합도를 낮추고 역할을 분명히 나눈다.
5. Unity 6 API와 현재 권장 방식을 따른다.
6. 코드뿐 아니라 필요한 GameObject, Component, Inspector 설정도 함께 설명한다.
7. 없는 에셋을 있다고 가정하지 않는다. 필요하면 임시 스프라이트나 기본 도형으로 대체한다.
8. 기능 단위로 구현하고 테스트하기를 반복한다.

## 13. 최종 목표
플레이어가 마을을 돌아다니며 모은 조각들이 사실은 모두 **플레이어에게 보내는 인사**였다는 것.
마지막 순간 게임 속 모두가 화면 너머를 바라보며 외친다.

> **"MERRY CHRISTMAS!!"**

게임을 끈 뒤에도 크리스마스카드 한 장을 받은 듯한 기분이 남는 것. 그것이 이 게임의 목표다.
